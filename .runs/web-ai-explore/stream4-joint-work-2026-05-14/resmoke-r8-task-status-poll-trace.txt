    ROOT CAUSE (architectural, pre-existing): taskRegistry is a module-scope
    in-memory Map. Each `node dist/src/cli.js` invocation is a fresh OS process
    with its own empty registry. generate-video's async job runs INSIDE the
    process that started it; a SEPARATE task-status CLI process cannot see it.
    The async chain is only coherent within ONE long-lived process (the MCP
    server `callMcpTool` path), NOT across independent CLI calls. The prior
    stub had the identical limitation; it was simply never live-tested.

    EVIDENCE the in-process async job DID run to completion: the authorized
    single generation produced a real 1,019,069-byte valid MP4
    (ftypisom container) at .runs/.../r8-video/mp_.mp4, and a real Gemini
    conversation "Blue Cube Video Generation" (app/76156170ddad8e72).
